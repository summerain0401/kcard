# aurora-glass 风格宪法

> 设计部交付物。本文件定义**什么不可违反**;可自由搭配的参数及其取值域见同目录 `space.json`。
> 2026-07-27 新建,kcard 的第三套风格。

## 一、这套风格是什么

暗色玻璃面板浮在几团硬边大色斑之上。色斑被画布边缘裁成弧形,
透过面板只剩极淡的色晕;面板本身近乎不透明的深炭色,靠**大半径背景模糊**
与一道顶边高光获得厚度。字体全部无衬线,字号小、字距大、留白多。

视觉张力来自**「浮起来」的物理关系**——色斑在下、玻璃在上、主体在玻璃上,
三层各自清晰,不来自透明度或发光。与另两套风格构成三角:
`editorial-mono` 是暗夜画册(竖排宋体、无圆角),`almanac` 是纸本图鉴
(横排衬线、无圆角),本风格是**当代产品视觉**(无衬线、大圆角、材质分层)。

## 二、构成要素(缺一即不成立)

| # | 要素 | 现行实现 |
|---|---|---|
| E1 | **硬边大色斑** | 2–4 个正圆,尺寸接近画布量级,必须被画布边缘裁切 |
| E2 | **无彩色斑** | 色斑中至少一颗接近无彩(近白或近灰),作为画面的呼吸口 |
| E3 | **深色玻璃面板** | 内缩于画布,承载全部文字,`backdrop-filter` 大半径模糊 |
| E4 | **顶边高光** | 面板左上角一道渐隐白,玻璃厚度感的唯一来源 |
| E5 | **章节导航片** | 一列/一排小玻璃方片,内含页码,当前页以 accent 描边——轮播的页码指示器。片数 = **轮播总张数**;超出固定尺寸能装下的片数时,片尺寸随页数自适应收缩(不砍片数,见 `engine.html` 的 `renderRail()`)。⚠ 配了专用封面(E12)时"总张数"= 1 张封面 + N 张正文页,正文页在轮播里的序号整体后移一位——`render.py` 通过 `renderCard()` 的 `railInfo` 参数把这个偏移告诉引擎。**片数数的是轮播张数,不是正文页数**,否则 4 张图的轮播上会写着「共 3 页」 |
| E6 | **玻璃小元件** | 标签胶囊、指标槽、引文块自身即小块玻璃,与大面板同材质不同厚度 |
| E7 | **字母印记兜底** | 无主图时用 `nameEn` 首字母的巨型描边字,而非 emoji |
| E8 | **无衬线全域** | 标题、正文、编号一律无衬线,与另两套风格结构性区分 |
| E9 | **手机可读的字号** | 正文 ≥ 26px(1080 画布)。2026-07-29 起画布定比例(3:4),缩略图可读性不再是内容量的函数,详见第四节 |
| E10 | **章节区的结构由骨架决定** | 引擎为每块输出 `data-i` / `data-style` 钩子、为容器输出 `data-n`,骨架据此排布。六个**整卡骨架**的章节区结构必须彼此可辨,不能只靠头版和配色区分。**封面骨架不受此条约束**——它没有章节区(E12) |
| E11 | **分页轮播** | 画布固定 3:4(`canvas.height: 1440`),内容池按引擎自动断页拆成封面 + 续页,输出多张 `output-NN.png`。2026-07-29 起是**全风格**的渲染方式,不再是骨架各自可选的能力,详见第五节 5.3 |
| E12 | **专用封面(唯一的可选要素)** | 生产组可在 `profile.json` 里配 `cover`,选一个**封面骨架**(`covers/*.css`)。配了则出图变成 1 张封面 + N 张正文页:封面独占 `output-01.png`,不放任何章节块,其上渲 `card.json` 的可选字段 `tagline` 作钩子。不配 `cover` 时整条路径不存在、风格照旧成立,故这是本宪法里唯一"缺了也成立"的要素。详见第五节 5.4 |

## 三、禁则(硬约束,机器可校验)

| # | 禁则 | 判据 | 理由 |
|---|---|---|---|
| H1 | 玻璃面板必须是深色 | `glass.lightness ≤ 0.26` | 浅色半透明面板即「小红书毛玻璃」,本项目已两次否定该方向 |
| H2 | 玻璃不得过透 | `glass.opacity ≥ 0.55` | 透太多则文字骑在色斑上,画面花、可读性塌 |
| H3 | 必须有真实背景模糊 | `glass.blur ≥ 20` | 没有 `backdrop-filter` 的深色板不是玻璃,只是深色板 |
| H4 | 面板必须浮于幕布之上 | `glass.lightness > scrim.lightness` | 面板比底幕暗就成了凹槽,三层关系反转 |
| H5 | 禁发光与彩色投影 | 不得出现彩色 `box-shadow` / `drop-shadow`;不得出现任何 `text-shadow` | 发光是「科技风模板」的标志,本项目明确排除 |
| H6 | 圆角必须足够大且统一 | `glass.radius ≥ 16`,面板与小元件共用同一套半径参数 | 小圆角在大面板上像未完成的方框;本风格是三套里唯一鼓励圆角的 |
| H7 | 必须无衬线 | 标题与正文字体栈均为 sans 族 | 衬线是另两套风格的地盘(E8) |
| H8 | 禁 emoji | 渲染产物中不含 emoji 码点,缺图走字母印记(E7) | emoji 是廉价感的主要来源 |
| H9 | 正文对比度达标 | `contrast(ink, glass) ≥ 4.5:1` | 可读性底线 |
| H10 | 分页模式禁止内容溢出画布(**仅正文页**) | 引擎为每页量面板按内容**自然撑开**的高度(临时摘掉定高与 flex 收缩再测,见 `engine.html` 的 `measureNaturalHeight()`),超出该页允许的高度即抛 `overflow`,`render.py` 收到后中止渲染并报 `RenderOverflow` | 与 H1–H9 不同,这条不是静态取值域校验,而是**渲染期**强制——固定画布不允许"内容太多就悄悄裁掉",宁可报错也不能默默丢内容。是本风格第一条不靠 `style-check.py` 而靠 `render.py` 本身兜底的硬约束。⚠ 早期实现直接量 `.panel` 的渲染盒子(`getBoundingClientRect().bottom`)判断是否超出画布——续页的面板是定高的,这样测永远测到那个常数,溢出检测形同虚设,内容会被 `.panel` 的 `overflow:hidden` 悄悄裁掉而不报错。改为先摘高度量自然值,再与允许高度比较,才是这条硬约束真正生效的写法。⚠ 2026-07-30 起须注意**适用范围**:专用封面(E12)不放章节块、不参与内容池分页、高度由封面骨架定死,因此不经过这道闸门。这不是给封面开后门——封面根本不存在"内容装不装得下"这个问题;闸门对正文页的防护范围一点没缩小 |

## 四、高级感判据(软约束,人评)

机器拦不住"合法但难看"。以下由设计部在**生产组上线时**一次性把关:

- **裁切**——色斑必须有相当比例落在画布外,完整的圆会读成图标而非光源
- **克制**——accent 只出现在章节编号、指标填充、导航首片描边、页脚圆点,不作区块填充
- **留白**——面板内边距与头版留白要足;这套风格靠空,不靠满
- **层次**——色斑 / 面板 / 主体三层的明度必须拉开;糊成一片时先压幕布,不要加发光
- **字距**——小号无衬线要给足字距,大标题要负字距;两者反过来立刻显廉价

### 字号判据(E9 的落地规则)

初版把正文定成 16px,是照桌面网页的习惯定的,**错了**。成品是 1080px 宽的图,
在手机上会被缩到约 36%,16px 到手机上只剩 6pt,不足该有字号的三分之一。
正文 **≥ 26px**(宪法 E9,`type.bodySize` 的取值域下限已按此设定)。

2026-07-27 到 2026-07-28 期间,这条判据还要跟"容量"一起看——那时是长图,
手机常按"整图适配"显示,卡片越长整体缩得越小,决定可读性的是
**正文字号 ÷ 卡片高度**,不是绝对字号。**2026-07-29 起画布定比例(3:4),
这层换算整个消失**:不管内容多少,出的每一张图都是同一个长宽比,
缩略图字号是常数,不再需要为容量单独判断。

### 内容池模型(2026-07-29 起:引擎自动断页)

`card.json` 的 `blocks[]` 是**内容池**,不是渲染清单,**没有数量上限**。
顺序即优先级,最重要的写在前面。引擎按以下规则把内容池切成多页:

```
量 —— 每页从当前位置贪心加块,加一块就实际渲染一次、测面板按内容
      自然撑开的高度(见 H10),超出该页允许的高度就回退到上一个装得下
      的块数,翻页
装 —— 重复上一步直到内容池耗尽
平衡 —— 末页只剩 1 块、且前一页 ≥3 块时,尝试从前一页借一块过来
        消灭孤儿页(借块后是否仍装得下,同样靠实际渲染测,不是拍脑袋)
报 —— renderCard() 返回总页数,render.py 据此循环渲染 output-01.png、
      output-02.png……
```

这套机制取代了 2026-07-28 那版的手调旋钮(`layout.coverBlocks`/
`layout.blocksPerPage`,已删除)——那两个数得逐骨架实测才敢定,加一版排版
就要重新试一轮。现在加一版排版**不需要量任何容量参数**,引擎自己会算。

**代价**:图数随内容长短自然浮动,同一套排版可能出 2 张也可能出 3 张,
这是刻意接受的——比起"为了凑固定张数而回头删内容",图数浮动的代价更小。

`data.blocks` 写多少、页数出多少,不受风格层面的上限约束;唯一的硬闸门是
H10(单独一块自己就比一页高时报错中止),不会静默裁掉内容。

## 五、边界

### 5.1 骨架 vs 引擎(2026-07-28 修订)

原先的分工是「骨架只负责头版五元素的定位」。那条线把章节区整个锁在引擎里,
结果是**换骨架只能换头版构图,章节区必然雷同**——三套风格的 section DOM 曾经
逐字节相同,骨架 CSS 连单个 section 都选不中。本风格自 2026-07-28 起改为:

| | 骨架(`layouts/*.css`) | 引擎(`engine.html`) |
|---|---|---|
| 管 | 头版元素定位、色斑落点、**章节区排布**:网格模板、跨列、顺序、逐块差异化 | 排版层级、配色、材质、块正文的内部构造 |

一句话:**骨架管「块怎么摆」,引擎管「块长什么样」**。

引擎为此输出三个钩子(E10),骨架用不用都行,不加 CSS 时渲染结果完全不变:

| 钩子 | 位置 | 用途 |
|---|---|---|
| `data-n` | `.grid` | 实际渲染的块数,骨架据此切换网格 |
| `data-i` | `.section` | 索引(0 起),骨架据此做逐块差异化 |
| `data-style` | `.section` | block 类型,骨架据此按类型排布 |

优先用 `data-i` 而非 `:nth-child`:前者指向**内容顺序**,后者指向 DOM 位置,
骨架一旦用 `order` 重排两者就会分叉。

内容层写死的 `span: "full"` 与骨架的跨列规则同特异度,而骨架 CSS 在引擎样式
**之后**注入,故骨架总能覆写它。各骨架应显式表态如何处置 `span-full`,
不要放任内容层的版式决策漏进来。

### 5.2 宪法 vs 参数空间

| 生产组可自由调 | 生产组不可越界 |
|---|---|
| 幕布/面板/文字的色相饱和明度(在 H1、H4 域内) | 不得把面板调浅、调透、调平(H1–H3) |
| 色斑数量、色相偏移、饱和明度、尺寸、模糊 | 不得让色斑全部有彩(E2) |
| 圆角、边框、顶边高光、投影强度 | 不得引入彩色投影或任何发光(H5) |
| 字号级差、字距、字重、无衬线字体栈 | 不得改用衬线(H7) |
| 栏数、栏距、面板内缩与内边距、主体尺寸、导航片尺寸 | 不得取消面板改为通版排字 |
| 换整卡骨架(六个任选)、配或不配封面骨架(E12)、覆写 `palette.accent` 恢复每卡取色 | 不得让六个整卡骨架的章节区结构退化成同一种(E10);不得把封面骨架当整卡骨架用(会静默丢掉全部章节内容,`render.py` 按目录区分即为此) |
| 封面的印记倍数与钩子字号(`cover.markScale` / `cover.taglineSize`) | 不得让封面承载章节内容——封面即海报,内容归正文页(E12) |

各维度取值域见 `space.json`。参数空间不够用 → 向设计部提案扩展维度;
需要改变上表右列 → 那是**另一套风格**,不是本风格的调教。

### 5.3 分页轮播(E11)

应用场景定在小红书/视频号图文——这两个平台是**固定比例、可滑动的图片
轮播**,长图会被信息流裁成封面比例,用户得点开再放大,等于在跟媒介对着干。
2026-07-27 到 2026-07-28 期间只有 `amber`/`onyx` 两个骨架试点分页,其余四个
仍是长图;**2026-07-29 起六个骨架全部分页**,长图模式对本风格彻底退场
(`canvas.height` 默认 `1440`,不再允许留空)。

**机制**:`canvas.height` 非空,`render.py` 就改用视口截图而非 `full_page`,
按 `renderCard(data, params, pageNum)` 循环渲染,写出
`output-01.png`、`output-02.png`……内容池按引擎**自动断页**分配到各页
(见第四节「内容池模型」),不再有 `coverBlocks`/`blocksPerPage` 这类手调
参数——2026-07-28 那版试点还需要逐骨架实测再定这两个数,现在引擎自己
量、自己定,加一版排版不用再算容量。章节编号全局连续(页二接着页一往下
排,不是每页各自从 01 重新数)。

**续页构图**:头版收缩到 `layout.contHeaderHeight`、标题按
`type.contTitleScale` 缩小,这两条由引擎统一处理;隐藏主体图、把空出的
宽度还给标题、**两栏改单栏**,这三条是**骨架职责**(通过
`.stage[data-role="cont"]` 选择器),因为不同骨架的主体位置与栏制不同。

⚠ **凡骨架的导航片是横排(贴头版底缘)的,续页标题下缘堆叠必须显式加上
`--p-rail-size`,不能按缩放后的标题字号去推。** `f-index` 曾经这样踩坑:
续页标题字号缩了(90→37.8px),但导航片不缩(仍是 `layout.railSize` 那么
高),按字号比例推出来的偏移量比导航片矮,副标题被页码条压住。另外三个
横排骨架(`b-panel-center`/`c-bleed-poster`/`e-mosaic`)封面规则里本就把
`--p-rail-size` 算进堆叠,续页沿用即正确,没有这个问题。

**续页(以及封面)的空白治理踩过三次坑,结论值得记住**:

1. 第一版只做了「面板撑满画布 + `.footer` 用 `margin-top:auto` 顶到底」。
   错的——那只是把空白从面板外挪到了面板内,画面依然是内容挤在顶部、
   下方一大片空。真正的空不在面板与画布之间,而在章节区内部。
2. 第二版让 `.grid` 吃掉剩余高度、`grid-auto-rows:1fr` 各块均分行高。
   也是错的——块撑满了,块**内部**却空了(4 个标签的块被拉到 500px 高,
   内容上下各空 175px),等于把「版面的空」换成「盒子的空」,更难看。
   由此定下前提:**留白留在版面上,盒子必须实**——玻璃片是「实体」,
   不是「容器」。
3. 第三版(现行)`align-content: center` 一度是对的,但自动断页取消块数
   上限后暴露短板:一页只装 2 块时,富余空间全堆在章节区上下两端,
   `d-timeline` 尤其难看(竖线贯穿全高,节点却挤在中段)。改为
   `space-evenly`,把同一份富余空间均摊到块之间与两端——盒子依旧饱满,
   留白变成"章节之间呼吸得开",而不是"中间一坨、两头两个洞"。

**面板必须封面与续页统一定高**,不能只给续页定高、封面留自动高——那样
封面内容一少,面板就缩成一小块浮在画布上方,下面空出一大片裸幕布,
比留白更糟。定比例轮播里"每张图的框一模一样"是前提,不是可选项。

**溢出检测必须量自然高度,不能量面板的渲染盒子**——续页(以及现在统一
定高后的封面)的 `.panel` 本身是定高的,`getBoundingClientRect()` 永远
测到那个常数,拿它判断"装不装得下"形同虚设,溢出会被 `overflow:hidden`
悄悄裁掉而不报错。必须先摘掉定高与 flex 收缩、量内容自然撑开的高度,
再与允许高度比较(详见 H10、`engine.html` 的 `measureNaturalHeight()`)。

**封面容量**:头版较高的骨架(`ember` 420px、`mist` 570px)封面往往只装得
下 1 块——这是接受的设计取舍,**封面即标题页**,不为凑够 2 块而回头压
`layout.headerHeight`。

### 5.4 封面骨架(2026-07-30 新增,E12)

`covers/*.css` 与 `layouts/*.css` **不是同一个品类,不可互换**:

| | `layouts/`(整卡骨架) | `covers/`(封面骨架) |
|---|---|---|
| 渲什么 | 正文页,内容池在这里按引擎自动断页 | 只渲一张,不放任何章节块 |
| 出图 | `output-02.png` 起(有封面时) | 独占 `output-01.png` |
| 入口 | `renderCard(data, params, pageNum, railInfo?)` | `renderCover(data, params, {totalPages})` |
| 受 E10 约束 | 是(章节区结构须彼此可辨) | 否(它没有章节区) |
| 受 H10 约束 | 是 | 否(高度由骨架定死,无溢出问题) |
| 选用方式 | `profile.json` 的 `layout` | `profile.json` 的 `cover`,**不配就没有封面** |

**为什么要拆出封面。** 目标平台的信息流里只有第一张会被大量人看到——它是缩略图,
是点击率的唯一来源。整卡骨架的第一页要同时承担"标题页"和"装内容"两件事,
结果两边都做不好:`f-index` 实测封面章节区有 820px 可用高度但只装得下 1 块,
剩下 469px 被 `space-evenly` 平分到上下两端,占封面高度 33%——既不是内容,
也不是构图。拆开之后,封面纯为缩略图而设计,正文页纯为阅读而分页。

**分工照旧是"骨架管怎么摆,引擎管长什么样"。** 字母印记在封面上的尺寸公式
(锚在画布高而非 `layout.heroSize`——后者是"头版里放个东西"的尺度,封面要的是
海报尺度)留在引擎,倍数由 `cover.markScale` 给,封面骨架只管摆到哪儿。

**渲染顺序是硬性的:必须先渲正文、再渲封面。** 导航片(E5)数的是轮播总张数,
封面要知道 `1 + N` 这个数,而 N 只有正文那趟渲完才知道。`render.py` 因此
另起一个页面渲封面(不是在正文那趟里换 CSS——骨架 CSS 是 `add_style_tag`
注入的,没有干净的撤销手段,换页重新 `goto` 才能保证两套 CSS 互不污染)。

**踩过一次的坑,值得记住:钩子行的 DOM 位置决定它的定位参照系。**
`.cover-tagline` 最初挂在 `.panel` 下,而标题、副标题、导航片都在 `.head` 里;
`.head` 是 `position: relative` 的参照系,两者基准不同,那套"自下而上逐层堆叠"
的算式于是对不上——实测钩子行直接压在导航片上。**凡是要参与头版堆叠的元素,
必须放进 `.head` 内部**。这与 5.3 记的那个"横排导航片必须显式加
`--p-rail-size`"是同一类错误的两种形态:堆叠算式的每一项都要真实存在且同源。

## 六、数据契约

复用 kcard 的通用卡片结构(`emoji` / `name` / `nameEn` / `category` /
`themeColor` / `hero` / `blocks[]`),因此**任何已有生产组的 card.json
不加字段即可切换到本风格渲染**。

本风格只新增一个**可选**字段 `tagline`(E12 的封面钩子行,缺省即整行不渲染,
不配 `cover` 时连读都不读)。`emoji` 字段被**刻意忽略**(宪法 H8):无 `hero` 时
不退回 emoji,而是用 `nameEn` 首字母渲染字母印记(E7)。因此 `nameEn`
在本风格下比在另两套里更重要——缺失时印记退化为 `name` 首字。

字段详解见同目录 `schema.md`。

## 七、已知偏离

- **字体依赖 macOS 系统字体**(PingFang SC / Avenir Next)。这是**有意接受的约束,
  不是待办**——本项目按 macOS 单机渲染设计,不追求跨平台一致。
- **`backdrop-filter` 依赖 Chromium**。渲染链路固定为 Playwright + Chromium,
  该属性在此环境稳定;若将来换渲染器需重新验证 E3/E4 的实际效果。
- **色斑位置属骨架职责**。引擎只算色斑的颜色与尺寸,`top/left` 全部由
  `layouts/*.css` 给出——构图是版式决策,引擎不替骨架决定。
