# editorial-mono 风格宪法

> 设计部交付物。本文件定义**什么不可违反**;可自由搭配的参数及其取值域见同目录 `space.json`。
> 2026-07-27 从既有 `card.html` 反向提炼,固化已有决策,未新增设计主张。

## 一、这套风格是什么

深色编辑排版(画册 / 杂志风)。视觉张力来自**排版层次**与**克制用色**,
不来自特效——竖排宋体大标题、Didot 衬线巨字、细线分章、衬线编号,
主体色只作点缀。适用于「一个主体 + 若干信息块」的百科式知识点。

## 二、构成要素(缺一即不成立)

| # | 要素 | 现行实现 |
|---|---|---|
| E1 | **极深底色**,且带冷暖倾向而非中性灰 | 四档 HSL 明度 0.032 / 0.052 / 0.076 / 0.112,自上而下渐次沉降 |
| E2 | **底色取主体色的互补色相** | `(accentHue + 180) % 360`,饱和 0.24–0.32 |
| E3 | **竖排中文大标题** | `writing-mode: vertical-rl`,宋体 900 字重,100px,字距 14px |
| E4 | **Didot 衬线巨字**作头版背景层 | 斜体 188px,极低对比度(accent 30% 混入 8.5% 白) |
| E5 | **细线分章** | 章节间 `1px` 细线,非色块、非卡片容器 |
| E6 | **衬线章节编号** | Didot 斜体 `01/02/…`,accent 色 |
| E7 | **纸感噪点** | `feTurbulence` 分形噪声,`mix-blend-mode: overlay` |
| E8 | **主体展台用细椭圆线** | 340×78px,`1px` 描边,替代发光底座 |

## 三、禁则(硬约束,机器可校验)

| # | 禁则 | 判据 | 理由 |
|---|---|---|---|
| H1 | 底色不得过亮 | 所有背景档位 HSL `L ≤ 0.12` | 极深底是本风格的地基 |
| H2 | 底色不得与主体色同色相 | `hueDistance(bg, accent) ≥ 120°` | 同色系会让主体淹没在背景里;黑配红之所以高级,正是对比让主体色达到最强冲击 |
| H3 | 主体色不得大面积使用 | 除头版 tint 圆外,accent 不得作任何区块填充;tint 峰值不透明度 `≤ 30%` | 克制是高级感的来源 |
| H4 | 章节不得使用 emoji 图标 | 渲染产物中章节区不含 emoji 码点 | emoji 是廉价感的主要来源(`icon` 字段保留仅为数据兼容,版式不展示) |
| H5 | 禁玻璃拟态 | 不得出现 `backdrop-filter` | 属"科技风模板"语汇,与编辑设计语言冲突 |
| H6 | 禁发光 | 不得使用正 spread 的 `box-shadow` 光晕或发光 `text-shadow`;投影仅允许纯黑向下 `drop-shadow` | 同上 |
| H7 | 禁胶囊圆角 | `border-radius` 仅允许用于正圆/椭圆装饰元素(tint、展台线);文字块与区块一律直角 | 圆角胶囊是小红书风的标志 |
| H8 | 标题必须衬线 | 大标题与章节标题用 serif-cn 族;拉丁与数字用 didot 族 | 衬线是本风格的字体骨架 |
| H9 | 正文对比度达标 | `contrast(ink-0, bg-floor) ≥ 4.5:1` | 可读性底线 |

## 四、高级感判据(软约束,人评)

机器拦不住"合法但难看"。以下由设计部在**生产组上线时**一次性把关:

- **克制**——accent 在整幅画面中读起来是点缀,不是主色调
- **层次**——字号级差必须拉开(现行 100 / 30 / 25 / 19 / 17.5 / 11)
- **非对称**——头版的竖排标题、巨字、主体三者不作居中对齐
- **呼吸**——大留白(现行头版独占 560px)

## 五、边界:宪法 vs 参数空间

设计部锁**构成要素与禁则**,生产组自由组合**具体取值**:

| 生产组可自由调 | 生产组不可越界 |
|---|---|
| accent 色相全域、底色饱和与明度档位、accent 微染比例 | 明度上限 0.12、必须互补色相 |
| 字号级差、字距、行距、字体栈(须仍为衬线族) | 标题不得改为无衬线 |
| 栏数、栏距、页边距、头版高度、主体尺寸、留白密度 | 分章不得改为色块或卡片容器 |
| 噪点强度、投影柔度、tint 峰值与尺寸、展台线宽 | 不得引入模糊、发光、胶囊圆角 |

各维度取值域见 `space.json`。参数空间不够用 → 向设计部提案扩展维度;
需要改变上表右列 → 那是**另一套风格**,不是本风格的调教。

## 六、已知偏离

- **hero 位 emoji 兜底**:无 `hero` 图时退化为大号 emoji(现行苹果 / 橙子 / 葡萄三卡)。
  这是**降级路径,不是合格形态**——正式出图必须配 AI 生成的无文字真实质感主图。
- **字体未自持**:现依赖 macOS 系统字体(Songti SC / Didot / PingFang SC),
  换渲染机器版式不一致。字体自持已列为设计部交付标准,待补。
