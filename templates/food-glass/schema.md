# food-glass 模板数据字段说明

深色编辑排版(画册/杂志风)知识卡片:竖排宋体大标题 + Didot 衬线巨字 + 细线章节
+ 衬线编号,主题色只用于编号、指标线等少量细节。用于「一个主体 + 若干信息块」
结构的内容,原型场景是食物百科(如西红柿),但字段本身是通用的,同样适用于其他
"主体 + 属性面板"类知识点。

> 命名说明:模板目录名 `food-glass` 沿用自最初的毛玻璃方案,现版式已改为
> 编辑排版风;因 card.json 以目录名引用模板,暂不改名。
> 字体依赖 macOS 系统字体(Songti SC / Didot / PingFang SC),换渲染机器需确认。

`card.json` 顶层结构:

```json
{
  "template": "food-glass",
  "data": { ... 见下 }
}
```

## 顶层字段(data)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `emoji` | string | 是 | 主体图标,单个 emoji。无 hero 图时作为主视觉 |
| `name` | string | 是 | 主体中文名(大标题) |
| `nameEn` | string | 否 | 英文名/拉丁名,展示在副标题左侧 |
| `category` | string | 否 | 分类信息(如"茄科 · 番茄属"),展示在副标题右侧 |
| `themeColor` | string | 否 | 主题色(hex),驱动背景光晕、图标底色、标签、进度条。**留空则由 render.py 从 hero 图自动取主色**(见下);既无本字段又无 hero 图时用模板默认橙红 |
| `hero` | string | 否 | 主图文件名(如 `hero.png`),相对本卡片目录。素材要求见下节。不填则用大号 emoji 作为主视觉,零素材成本 |
| `blocks` | array | 是 | 信息块列表,见下。数量、顺序、种类完全由数据决定,模板不做任何硬编码假设 |

## blocks[] 每项字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `icon` | string | 否 | 保留兼容字段,现版式**不展示**(用衬线章节编号 01/02 取代 emoji 图标) |
| `title` | string | 是 | 信息块标题(如"核心功效""食用方法""营养价值""食用注意""适合人群""冷知识") |
| `style` | string | 是 | 内容呈现方式,见下表 |
| `span` | string | 否 | 值为 `"full"` 时该块占满整行(默认占网格中一格,两块并排) |
| `items` | array | 视 style | `list`/`tags`/`metric` 需要 |
| `text` | string | 视 style | `text` 需要 |

### style 取值

- **`list`**:要点列表。`items` 为字符串数组,逐条竖排,带小圆点。
  适合"核心功效""食用方法""食用注意"等。
- **`tags`**:标签云。`items` 为字符串数组,渲染为并排色块。
  适合"适合人群"等简短并列项。
- **`metric`**:指标条。`items` 为对象数组 `{"label", "value", "percent"}`,
  `percent` 为 0-100 的数字,驱动进度条长度。适合"营养价值""含量指标"。
- **`text`**:整段文字。用 `text` 字段(字符串)。适合"冷知识"这类一句话内容,
  通常搭配 `"span": "full"`。

## 主图(hero)素材要求

本模板是**深色底**,主图素材必须配合,否则主体会被自己的背景拖累:

- **背景必须透明(PNG 抠图)或纯黑**,主体去底。这是硬要求
- **画面内不得含任何文字/水印/logo**(否则违背"文字零错误"的前提)
- 正方形构图,建议 ≥1000×1000px,主体居中

生图 prompt 里**不要写"浅色/米白/暖色渐变背景"**。踩过的坑:带浅色底的素材放到深色卡上,
会在主体周围糊出一圈白雾,羽化只能软化边缘、救不了中心;而主体边缘在同色系背景上
对比度过低,事后用彩度阈值自动抠图也做不干净。

### 拿到的素材带底怎么办

AI 生图工具经常无视"透明背景"要求,导出纯白底,或把透明网格烤进像素。
只要背景是**中性色**(R≈G≈B),用 `scripts/cutout.py` 键掉即可:

```bash
python scripts/cutout.py cards/<topic>/hero.png    # → hero-cut.png
```

然后把 `card.json` 的 `hero` 指向 `hero-cut.png`。脚本在主体占比异常时会告警:
<2% 说明阈值太狠把主体也键掉了(调低 `--light` 或调高 `--chroma`);
>90% 说明背景带色相没键出,这种素材**只能重新生成**,自动抠图救不回来。

参考 prompt(英文):

> A whole fresh {主体}, {材质/风格描述}, 3D render, product photography style,
> soft studio lighting with rim light, centered composition,
> **transparent background, cutout, no background**,
> no text, no watermark, no logo, square 1:1, high detail

负面提示词:`text, watermark, logo, plate, hand, background, gradient background, cartoon`

## 主题色自动取色与配色推导

配色核心原则:**底色不用主体色,用与主体色相配的色**。主体色和底色同色系时,
主体会淹没在背景里;黑配红之所以高级,是因为对比让主体色达到最强视觉冲击。

因此 themeColor 推导出两套角色:

| 角色 | 取值 | 用途 |
|---|---|---|
| 配对基色 | 主体色**互补色相**(+180°),饱和压到 ~0.3、明度压到 0.03~0.11 | 背景四档。读起来是"有冷暖倾向的高级黑",不是彩色背景 |
| 主体色本身 | themeColor 原值 | 章节编号、指标线、分隔线、正文微染 —— 细节呼应主体 |

效果:番茄红 → 深青黑衬底;香蕉金 → 深蓝黑衬底;葡萄紫 → 深橄榄黑衬底。
底色始终是黑,但各自冷暖不同,既保证主体跳脱,又随主体动态适配。

> 实现注意:互补色推导在模板 JS 里做(CSS 无法旋转色相),
> 结果写到 `documentElement` 的 `--bg-floor/deep/mid/hi`。
> 文字/线条等 color-mix 派生色声明在 `.stage`,不能挪回 `:root`——
> var() 在声明处求值,历史上曾因此导致"换色不生效"。

`themeColor` 不填时,render.py 会从 hero 图提取主色,换素材即自动换配色:

- 只统计主体像素(alpha 高、有饱和度、非阴影非高光),按色相直方图取峰值
- 提亮提饱和后输出——素材本身明度往往偏低,直接用在深色底上会发闷
- 无随机性,同图重复取色结果一致(符合项目的确定性渲染约定)

想手动定色就填 `themeColor`,显式值永远优先。取色结果会打印在渲染日志里。

## 关于信息块的选择

模板不区分"这块内容属于哪种主题维度",只认 `title` + `style`。填数据时按
该食物/主体实际有价值的维度挑选、命名、排序即可,缺的维度不必凑数。
常见维度示例(非强制枚举):核心功效、食用方法、营养价值、食用注意、含量指标、
适合人群、冷知识。

## 尺寸与产出

- 画布宽 1080px,高度随内容自适应(render.py 用 full_page 截图)
- 2x 设备缩放,输出实际像素为 2160px 宽
